# Restart version 20: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a restarted run reproduces the continuous run byte for byte in every case the audit made exact, through one new restart version, v20.

**Architecture:**
- **The record.** v20 adds `iwetv`, `evapv`, `windcd` and a heat flag with `tws`/`dtw` to the hydro block (id 1), and the k-epsilon `tken`/`eps`/`visv`/`difv` to the turbulence block (id 8).
- **The state behind it.** Two `save` locals become module state, so a restart can restore them: the `setweg` clock and the COARE skin temperatures. The k-epsilon start-up stops overwriting restored values.
- **The tools.** The reader, `rst_skip_record`, `rstinf` and `rst2shy` learn v20. v17–v19 files read as before.

**Tech stack:** Fortran 90 (gfortran, OpenMPI build), bash check scripts, and Python 3 with numpy for the `.shy` comparison.

**Spec:** `docs/superpowers/specs/2026-11-26-restart-v20-design.md` (approved by the owner on 2026-11-26).

**Evidence:** `docs/investigation/2026-11-restart-v20/`. It holds `reportI304.md` and `reportI304b.md`, the scripts in `tools_i304/` and `tools_i304b/` (`shycmp.py`, `extcmp.py`, `mkmm.sh`, `mkven.sh`, `heatcase.sh`, `venmpi.sh`), and the tested throwaway patch `tools_i304b/i304b_throwaway.patch`. The patch is against fd9bd17c; strip its `I304_SKIP`, dump and side-file parts.

**Results:**
- Only restarted runs may change, toward the continuous run. Every non-restarted output stays byte-identical to origin/main (show it with `cmp`).
- New `.rst` files are v20. Every gate that compares `.rst` files with the base is named in the PR as this change's exception.

**Compatibility:** v17, v18 and v19 restart files are read exactly as by origin/main.

**When each new field is applied** (spec §"What the v20 record adds"):
- `iwetv` and `evapv`: always.
- `windcd`: only if the reader's `itdrag` is 4 or 3.
- `tws`/`dtw`: only if the file's heat flag is set.
- the k-epsilon arrays: only if the file's and the reader's `iturb` are both 2.
- the `setweg` clock reset: only when hydro is restored.

**Fortran rules:** `implicit none`; `intent` on every argument; allocations checked; no bare `stop` on a path that runs on several processes; no short-circuit guards.

## Review Focus
1. **A v19 (or v18) restart file read by the new code** continues exactly as main continues it. Pinned in Task 3, step 1, case `old_v19`.
2. **A reader with `itdrag = 0` and a v20 file whose `windcd` came from COARE:** the user's `dragco` is used, not the stored values. Pinned in Task 3, case `drag0_reads_cd4`.
3. **A k-epsilon restart file read by a GOTM run** (`iturb` 2 → 1): GOTM starts from its own initial state, never from unset arrays, and the run completes. Pinned in Task 4, case `keps_to_gotm`.
4. **A restart read with a `flgrst` subset that excludes hydro:** the new hydro-block records are skipped cleanly, and the clock is not reset. Pinned in Task 3, case `flgrst_no_hydro`.
5. **A restart read on several processes** (wet/dry `venlag`, 2 and 4 processes): exact, like serial. Pinned in Task 1 (the cases) and Task 3 (GREEN).
